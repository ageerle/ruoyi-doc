# RuoYi-AI 商业版正式发布：让 AI 用上企业知识，把工作经验留下来

![RuoYi-AI 商业版正式发布](/images/commercial/ruoyi-ai-commercial-release-cover.png)

RUOYI-AI · 商业版发布

让 AI 用上你的知识，<br>
按你的业务方式工作。

今天，我们正式发布 <strong>RuoYi-AI 商业版</strong>。

如果你已经在团队里用过 AI，可能遇到过这些问题：客户资料分散在不同表格里，工作要求每次都要重新解释，一次做对的方法没能留下来。等使用人数多了，还需要知道大家怎样使用、模型调用花了多少。

这次商业版，我们围绕这些日常工作，把<strong>知识图谱、长期记忆、Skills 技能沉淀、人机协同、个人工作台，以及会话统计和计费管理</strong>整合起来。下面用一套企业联系人案例，带你看看它们怎样用在业务里。

先从一句问题开始：<strong>“帮我查一下陈明在哪家公司，怎么联系？”</strong>

文中截图来自产品实际运行。联系人、公司和联系方式使用虚构演示数据。

01 / 知识图谱

## 记得一个名字，就能顺着关系找到资料

找到了姓名，往往还没完成工作。你还需要知道他在哪家公司、负责什么、该用什么方式联系。我们把这些业务信息连接起来，让查人、查企业和查产品有一条清楚的路径。

<strong>输入你的问题</strong>

「陈明在哪家公司任职？他的工作电话和邮箱是什么？」在这套企业联系人演示中，RuoYi-AI 返回示例智造科技有限公司、销售经理、138****0000 和 chen.ming@example.com，同时给出资料来源。

<strong>人物与公司，一起查。</strong>从联系人出发，查看所属企业、岗位和联系方式。销售交接时，可以把同一人的信息放在一起核对。

<strong>关系可看，结果有依据。</strong>通过关系图查看人物、企业与产品的连接，结合来源资料核对答案，方便追查信息从哪里来。

<strong>围绕你的资料扩展。</strong>以联系人查询为起点，逐步整理产品负责人、客户名录或供应商关系。图谱检索也可以接入绑定图谱的智能体。

02 / 人机协同

## 关键一步，让 AI 先问你

同一家公司里，销售和技术支持往往是不同的人。你的业务意图决定下一步该找谁。我们把选择卡片放进对话，让你在需要的时候参与决策，确认后继续完成任务。

<strong>选择一次，继续处理</strong>

在联系人对接演示中，AI 先问「本次需要联系销售还是技术支持？」。点击「销售对接」，它便按本轮提供的联系人资料整理陈明的信息表，并给出核对流程和交接清单。

![把选择放在对话里](/images/commercial/user-hitl-question.png)

把选择放在对话里<br>
选择业务方向，也可以补充自己的要求。上下文保留在当前任务中。

![确认后，继续生成业务结果](/images/commercial/user-hitl-completed.png)

确认后，继续生成业务结果<br>
销售联系人的信息和核对流程一起呈现，后续要求可以直接在同一会话里补充。

<strong>意图不清，先确认。</strong>销售、技术、商务等对接方向，用选项表达清楚，减少来回解释。

<strong>信息不足，补充再继续。</strong>同名人员、多个候选或缺失条件，可以通过对话继续确认目标。

<strong>你参与，任务不断开。</strong>你的选择回到当前任务，AI 接着处理已有信息，免去重新描述整个需求的步骤。

人机协同用于对话中的信息补充与意图确认；业务系统的审批和操作权限可按项目要求另行对接。

03 / 记忆管理

## 你的工作习惯，下次还能接着用

表格用哪些列、资料缺失怎么处理、遇到同名要不要确认，这些要求不必每次重新解释。我们提供可以查看和修改的个人记忆，让稳定的工作偏好跟随你的账号。

<strong>把要求保存下来</strong>

在这次演示中，我们保存了联系人表的六列顺序，以及同名先确认、演示信息要标注的要求。换到新会话，AI 读取长期记忆，仍然能说清楚应该怎样组织这份表格。

![记住了什么，你看得见](/images/commercial/user-memory-current.png)

记住了什么，你看得见<br>
长期记忆和每日记录放在个人设置里，内容摘要、更新时间和编辑入口清楚可见。

![换个会话，也能读取原来的要求](/images/commercial/user-memory-recall.png)

换个会话，也能读取原来的要求<br>
姓名、公司名称、职务、电话、邮箱、资料来源，这套列顺序被从已保存的记忆中读出。

<strong>偏好可以积累。</strong>把稳定的格式、措辞和工作要求保留下来，为后续对话提供上下文。

<strong>变化可以修正。</strong>当流程或偏好改变，直接修改或删除已有记忆，让保存的内容跟上工作变化。

<strong>管理有入口。</strong>个人维护自己的记忆，管理员也有集中查看和维护入口，便于处理过期内容。

个人记忆适合保存工作偏好；客户、产品和企业的共享事实，建议由知识库、图谱或业务系统统一维护。

04 / Skills 技能进化与沉淀

## 这次做对的方法，下次可以继续用

一份联系人交接单，真正值得留下的是背后的工作方法。我们让会话中的纠正、有效步骤和核对规则有机会成为技能草稿，再由管理员审核，把经过选择的经验留在系统里。

在这次联系人演示中，销售对接结果附带了未选中的技术联系人。我们在对话里明确了规则，正式名单只保留选中者，缺失邮箱标为待补充，同名人员先确认。

修订后，再检查同名、缺失邮箱两种情况。系统据此生成了<strong>《单目标联系人对接与交付规范》</strong>，包含适用场景、操作步骤、异常处理和验收清单。

具体的人名和联系方式留在业务资料里，通用方法进入技能。这正是我们希望为团队留下的东西。

<strong>① 在任务中积累</strong> · 记录要求、纠正和有效做法

<strong>② 复盘形成草稿</strong> · 提炼适用场景与操作步骤

<strong>③ 管理员审核</strong> · 检查方法、内容和来源

<strong>④ 纳入技能管理</strong> · 审核通过后，供后续会话加载

<strong>适合沉淀的内容</strong>

联系人核对、交接单整理、缺失信息处理、资料来源检查。你可以从一套经常重复的工作方法开始，逐步建立适合自己团队的技能。

技能进化通过生成、审核和复用工作方法实现，不涉及大模型权重训练。系统会筛选可复用的经验，并非每次对话都会生成技能。

05 / 用户级模型、工具与技能

## 把常用能力，放进自己的工作台

销售需要客户资料和对接流程，技术支持需要问题说明和处理方法。我们把模型、MCP 工具、技能、知识库与记忆集中到个人设置中，让不同岗位可以组合适合自己的工作资源。

<strong>模型连接自己管理。</strong>维护个人模型、供应商连接与 API 凭证，选择已配置的模型开展工作。

<strong>工具与技能各有用途。</strong>通过 MCP 接入可用工具，通过技能保存工作方法。结合平台审核与启停管理，让资源使用有明确入口。

<strong>资料与偏好集中维护。</strong>在同一处找到知识库和记忆。准备资料、调整偏好之后，回到对话即可继续任务。

06 / Token 统计与计费

## AI 用了多少，费用从哪里来，看得清楚

当企业里有更多人开始使用 AI，管理者需要看清每个账号的调用与开销。我们把输入、输出、缓存命中和费用记录到调用账本里，让使用规模扩大时，成本仍有据可查。

<strong>每次调用，留下明细。</strong>记录模型、用量、调用状态和价格快照。一个任务触发多次模型请求，也能分别查看。

<strong>每个账号，有自己的账本。</strong>用户查看本人余额、用量和最近调用；管理员从用户汇总进入明细，了解费用构成。

<strong>额度调整，保留原因。</strong>管理员可以调整余额并留存流水。余额和待结算金额一起参与校验，为内部额度管理提供依据。

### 管理端会话统计：看清团队怎样使用 AI

推广 AI 助手后，团队是否开始使用、请求量如何变化、Token 消耗是否增长，都可以在「对话分析」中查看。我们提供最近 7 天、30 天和 90 天的统计视角，将新增会话与累计会话、对话请求与助手回复、MCP 和工具调用放在同一个运营入口，帮助你持续跟进使用情况。

<strong>会话规模，一眼掌握。</strong>查看本期新增会话和会话总数，结合请求与回复数量，了解团队的使用情况。

<strong>用量变化，按时间观察。</strong>查看对话请求、MCP 与全部工具调用趋势，以及 Token 消耗趋势，便于关注推广后的资源变化。

<strong>能力建设，也能跟踪。</strong>查看 MCP 配置与 Skills 数量、系统和个人分布，以及 Skills 新增趋势，了解可用能力的积累情况。

07 / 对话配置

## 把企业品牌和运营参数，交给后台管理

网站名称换了、版权说明要更新、邮件服务需要调整，这些变化都有可操作的配置入口。我们将站点、邮件、支付与微信参数分组呈现，方便管理员按业务需要维护。

<strong>展示你的品牌。</strong>设置网站名称、Logo、版权说明和客服入口，让企业 AI 门户使用自己的品牌信息。

<strong>分组维护服务参数。</strong>站点信息与邮件服务等分别编辑、保存，管理者能清楚知道本次修改了什么。

<strong>为渠道接入做好准备。</strong>微信、支付等服务的参数集中配置，便于后续账号对接与联调。

08 / 微信运营接入

## 把服务入口，放到用户熟悉的微信里

如果你的客户从公众号认识你，员工习惯在企业微信里沟通，微信就是值得连接的业务入口。我们提供扫码登录与消息回调接入基础，方便围绕企业已有账号继续建设 AI 服务。

<strong>公众号扫码入口。</strong>参数二维码、扫码事件与登录轮询，为用户从微信进入服务提供连接能力。

<strong>企业微信回调。</strong>回调校验、消息解密和事件路由，为企业微信与业务服务的衔接提供基础。

<strong>统一维护接入参数。</strong>在后台配置微信账号参数，让渠道接入与企业门户一起管理。

<strong>可以这样规划服务</strong>

客户通过公众号扫码进入企业 AI 门户，再访问授权的产品资料或服务助手；员工通过企业微信连接内部服务。根据你的账号类型与业务流程，确定消息回复、用户身份和后续业务处理方式。

微信接入需要你提供可用账号、凭证和符合平台要求的回调域名。当前交付基础为扫码与回调接入，AI 客服回复、群发运营和 CRM 线索流转需按项目扩展。本页不展示微信联调截图。

09 / AgentScope 框架

## 让模型、工具与业务步骤协同执行

企业任务通常要经过多个步骤。我们使用 AgentScope Java 2.0.3 与 Harness 组织通用对话执行，将模型调用、工具使用、技能加载、记忆和人工询问放进同一套任务流程。

<strong>接住业务请求</strong>：识别用户与会话；使用对应模型配置；读取工作偏好与上下文；通过 SSE 展示实时进度。

<strong>组织任务执行</strong>：调用 MCP 工具；加载适用的技能；连接已绑定的知识图谱；需要信息时向用户提问。

<strong>保留结果与经验</strong>：持久化会话与工作区内容；记录调用级 Token 用量；复盘并提炼技能草稿；衔接管理员审核流程。

<strong>技术怎样服务业务</strong>

在联系人场景里，ask_user 承接你的选择，模型继续整理结果，账本记录用量，复盘机制提炼核对方法。产品中这些连续的操作，由任务执行框架和业务模块共同支撑。
